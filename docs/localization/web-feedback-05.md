# 祭坛、握持说明、鉴定消息及构建版本反馈

1. WebTiles 的神祇说明原先用必须以英文句号结束的正则表达式拆分神力与消耗，并直接读取匹配结果。中文神力使用中文句号或没有句号时，匹配返回 null，导致整个窗口显示 `Buggy UI of type describe-god`。现在支持中英文句号和括号；无法拆分的新文本整行保留，不阻断祭坛窗口。颜色通过原格式转换器呈现，空信息表不再插入空容器。祭坛、普通神祇说明和观战共用同一路径。

2. 机甲哥布林的 `grasper` 和骚灵的 `tendril` 不在握持说明所用 `a.bodypart` 目录内，导致整句按方针回退英文。新增两项复用既有“抓握器”“卷须”译名，完善数量表达；规范英文说明不变。原生测试覆盖机甲哥布林、骚灵、人类、章鱼人。

3. 鉴定消耗品时重新分配快捷字母的消息直接调用规范英文名称。现在先尝试已有物品显示名称，保留旧／新字母、数量、物品数据和分配逻辑；名称无法完整翻译时仍显示原英文。消除药水、鉴定卷轴的中英切换均有测试。

4. `quivered` 的物品状态显示统一为“已备”，避免把所有备选动作误称为投掷。现行术语表及早期静态条目映射同步更新；英文状态键仍为 `quivered`。

5. Linux 构建依赖 `git describe` 时，缺少新标签的服务器可能选中旧 `0.25-a0` 标签。新增 `util/version_base`，固定此分支真实上游版本及提交：`0.34.1`、`1eebc1a2892e1c89776a0d7a10691f8dac8d9796`。游戏版本头、Makefile 版本、WebTiles version.txt 和源码包版本统一由 `source-version.pl` 生成。完整历史生成 `0.34.1-N-g<提交>`；浅历史无法确认距离时生成 `0.34.1-shallow-g<提交>`；无 Git 的源码包使用匹配的 release_ver 或基准版本。将来升级上游时必须同时更新基准版本与基准提交，不能仅改版本字符串。旧存档和 morgue 中已记录的历史版本不追写修改。
