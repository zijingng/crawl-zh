# database 第三批续译：小鬼与恶魔嘲讽

## 覆盖与术语预查

`database/insult.txt` 全部 33 个键、535 个文字候选完成翻译，覆盖普通小鬼／恶魔嘲讽、逃跑和投降威胁、身体与精神部位、食物称呼，以及精灵、猫族、矮人、天狗、木乃伊、吸血鬼、斯普利根和牛头人相关辱骂。另补齐 27 个不同的说话／叫声动词。

翻译前逐条查询 `localization/glossary.csv`，原始命中、术语表 SHA-256、各英文正文哈希及说话动词预查见 [预查记录](database-03-preflight.json)。保留英文文件、英文键、全部候选和原有权重；535 个候选中的同义词和重复含义也没有合并。旧式英语和戏谑造词按中文辱骂语气表达，保留原候选对应关系。

术语使用地精／狗头人、豺狼人、牦牛、丧尸等既有译名。以下命中按句意区分：

- `will` 在精神部位中译为“意志”，在 `will_or_shall` 中为将来／决意语气。
- `spirit` 在此为精神或灵魂，不套用装备词条“灵魂护盾”。
- `Fly` 在逃跑威胁中为“飞走吧”，不是飞行状态标签；`turn tail` 为“夹着尾巴逃吧”，不是回合。
- 普通名词 `nobody` 为“小人物”，不是独特怪物“无名氏”。`earth`、`light` 等也不机械套用装备词条译名。

译文保存于 `localization/zh_CN/textdb.po`，通过审核清单生成 `dat/database/zh/insult.txt`；严格双语配对所需的完整正文同时进入 UI 目录。

## 动态接入与英文回退

`do_mon_str_replacements` 在原有种族专属辱骂查询的位置取得双语结果，并保留三次查询的原有顺序。即使当前句子没有用到全部三个占位符，仍执行上游原有的三次查询，不跳过随机抽取，也不为中文额外抽取。没有种族专属候选时，沿用原有通用辱骂回退。

`@says@` 使用同一个已确定的声音类别翻译为“说道”“吼道”“低语道”等；保留原有频道、喊声类别和噪音逻辑。怪物名称、嘲讽正文、种族辱骂或说话动词任一部分不可译时，整句保留英文。

中文 `insult.txt` 是审核导出物，实际配对显示由带源文和代码依赖哈希的 UI 目录提供。中文 TextDB 的旧式覆盖加载器专门跳过该文件，以免尚未适配的 `monspeak.txt` 把中文辱骂片段嵌入英文句子；英文数据库和其他语言的加载逻辑不变。这也避免旧覆盖文件绕过严格配对检查恢复陈旧译文。

真实 SQLite 数据库还验证了上游读取器对文件末条 `insult mummy noun` 多保存一个空行的行为。本批为这个已实测的正文形式另登记精确译文，并保留文件本身的形式；没有修改英文文件或放宽运行时匹配。两种形式均绑定同一源文件和渲染代码哈希。

本批主要补齐 `shout.txt` 中 `__DEMON_TAUNT`、`imp` 及其别名引用的缺译。`monspeak.txt` 的完整怪物对白仍需继续逐条审核与接入，不能因为共享辱骂词库已译就认作全文已覆盖。

## 验证

新增原生测试使用工作区内的独立 TextDB 缓存，实际加载中文数据库，检查全部 33 个键在九种玩家种族、多个声音类别和随机种子下的输出：英文结果与原有非配对替换过程一致，中文不残留英文候选或占位符，切回英文和随机状态保持一致。

另检查真实小鬼／恶魔喊声、不可用组件的整句回退，以及中文模式下旧 `getSpeakString` 接口仍返回完整英文嘲讽，防止中英片段混用。缓存保存在工作区 `.term-audit/database-03-runtime/`；没有访问玩家存档。

导出和构建检查结果见 [检查记录](database-03-checks.json)。尚未进行实际 Tiles 窗口视觉验收。
