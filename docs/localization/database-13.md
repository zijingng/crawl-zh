# database 第十三批：食物储藏点及种族／形态消息

本批补译 `database/decorlines.txt` 食物部分的全部 **71 个键、119 个候选**，包括水果、肉食、烘焙食品的根条目，以及食肉／无需进食等饮食、种族和变身形态的入口句及别名。

翻译前查询术语表，并对复合怪物名和英文形容词对应的规范名补查，记录见 [预查清单](database-13-preflight.json)。使用“梦羊”“死亡牦牛”“蝰蛇”“短吻鳄”“海妖”“海德拉”“魔窟”“狗头人”“斯普利根”“天狗”“娜迦”“食尸鬼”“宝库守卫”“星之花”等既定译法。原来的食物堆键、种族名和形态名保持英文规范标识。

## 翻译及结构

三个食物根条目同时保留物品描述和味道评价，由入口句引用生成完整消息。例如“你俯身尝了一个苹果。清脆。”不会把已带英文冠词的显示串直接嵌入中文。

句式覆盖翻找、啃食、吞食、磨碎、电解、刀刃当筷子、龙人尝火龙果、斯普利根挑掉披萨上的肉等原文细节。不调整游戏规则，也不把装饰性味道描述转成新的属性效果。部分食物使用音译或通用菜名，不擅自把它们认作实际游戏物品类型。

保留全部权重、引用和方括号选项顺序。原文 `[dwarven|kobold|kobold]` 与 `[trollish|giant|giant]` 的重复选项分别保留为 `[矮人|狗头人|狗头人]` 与 `[巨魔|巨人|巨人]`，不去重，以免改变随机概率。别名仍引用英文键，选中哪个食物候选只由原有的一次随机过程决定。

## 显示与英文回退

本批复用上一批的严格配对显示，没有修改游戏 C++ 或 Lua 逻辑。食物消息的根条目及其依赖一起进入已审目录；源文不匹配、引用失效或组件不可用时，整句回退规范英文，不混用旧子条目。

文件最后的 `vampire baked goods cache` 在运行时数据库中多一个 EOF 换行。本批从实际英文缓存读取该正文，确认仅末尾换行不同后，单独登记精确匹配版本，并绑定相同的源文件和渲染代码哈希。没有改成忽略原文变化的宽松匹配。

累计已审导出 **120／132 键**，还剩 12 个键：默认喷泉的 Lua／涂鸦消息，以及 `Elyvilon`、`Gozag`、`Makhleb`、`Okawaru`、`Trog` 的相关引用或武器／Lua 消息。未把剩余内容标为已审。英文文件按字节保持不变，上一批 49 条已审正文保持不变。

## 验证

现有实际 TextDB 原生测试扩大到全部 120 个已审键，每键使用 128 个随机种子，对比中英文、英文原始处理结果及后续随机状态。覆盖文件末尾变体、嵌套食物引用、重复选项和整句回退。

数据检查逐条核对 PO、权重、引用和方括号结构。隔离数据中修改烘焙食品子条目后，确认其根条目、多层别名及吸血鬼入口的旧译全部拒绝导出，而水果和肉食分支仍可用。

Windows Tiles 编译、工具测试及原生回归结果见 [检查记录](database-13-checks.json)。未进行实际游戏窗口视觉验收。整个 `dat/database` 仍未全覆盖。
