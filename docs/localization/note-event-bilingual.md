# Note 双语正文：事件发生时生成

本方案取代旧文档中所有 note 快照与显示时重建方案。

## 写入与读取

`take_note` 在事件仍有完整上下文时生成英文、中文两份完整正文，保存到 `Note::english`、`Note::chinese`。数字、地点、类型、原名称和来源等上游字段保持原含义；`desc` 不再存放中文快照，`screen` 仅用于用户截图。

普通类型记录在 `take_note` 内生成双语正文。物品、地形、开局、升级、版本变化、Lua 区域记录、受伤与死亡等动态记录，使用现场对象通过同步回调生成中文。回调只运行一次，不重放游戏行为；不为翻译重新产生随机选择。当前界面是英文时也生成可用中文，之后切换语言、读档和导出不依赖原场景。

`Note::describe` 默认返回已保存的英文；显式请求本地化且当前为中文时，选择已保存的中文。缺译或组件不完整时整条使用英文。回合、地点前缀仍由原有输出路径处理。已生成的正文不会随日后术语修改而重新翻译。

## 已删除的实现

- `display_describe()` 和 7 个 `make_*_note` 构造辅助函数。
- 开局、等级、版本、物品、区域、地形／商店、魔窟领主来源、伤害、死亡共 9 类、11 种快照标记的写入和解析。
- 物品二进制序列化／十六进制快照、完整 score 快照和伤害 xlog 快照。
- 根据旧快照重新构造物品、商店、死因或区域的兼容路径。

原有 `scorefile_entry` 中文显示方法保留，用于在死亡／受伤事件发生时生成正文，也继续服务高分显示；不再通过 note 中的 score 快照调用它们。

## 存档与英文回退

使用 `TAG_MINOR_BILINGUAL_NOTES` 为两个新增正文字符串标识存档版本。旧布局仍能按原字段读入，但不解析、不迁移旧中文快照，也不补译旧记录；没有已保存双语正文的历史记录显示原英文。旧程序不能读取新增版本产生的存档。

英文 morgue 的默认路径和正文不变。中文仍另行生成 `.zh.txt`；用户手写记录和截图保留原文。未审或依赖失配的译文仍不进入运行目录。

## 验证

定向回归覆盖：事件时一次生成、英文界面创建中文正文、语言恢复、未知组件整句回退、正文不随当前场景变化、存读档、死亡与非致死伤害、实际 Lua 区域记录、实际物品鉴定与地形发现、中英文 morgue 文件以及随机状态不变。旧快照专用测试已改成事件生成测试；普通类型和所有变异等级的覆盖保留。

验证结果：Windows Tiles `crawl.exe` 与原生测试程序编译、链接成功；19 项定向原生用例、8,136 条断言通过；47 项 Python 检查通过。已审 UI 译文依赖失配为零，23,202 条已审译文进入目录，1 条未审条目继续排除。`git diff --check` 通过。未执行全量原生用例。
