# database 第二批续译：颜色、花纹、喊声与谜语

## 覆盖结果

本批先逐条查询术语表，保存术语表及源文 SHA-256、命中词和既有审核目录检查至 [预查记录](database-02-preflight.json)。英文数据库未修改。

| 文件 | 结果 |
| --- | --- |
| `database/colourname.txt` | 9 / 9 个条目全覆盖，含 370 个杂项颜色候选，以及彩虹色、黑白灰、亮度、花纹与递归组合 |
| `database/shout.txt` | 93 / 93 个键完整导出；补齐鸦鸣、狂笑、斯芬克斯谜语等遗漏，并校对原有喊声的所有格、代词和声音措辞 |

颜色、亮度和花纹共 424 个基础候选；随机组合、原有权重、重复候选和候选顺序均保留。`shout.txt` 的 93 个键中有一个原文为空的分隔条目，按原样保留，不计为新增可见译文。本批新增 20 个含显示内容的缺译键，另保留这个空条目，并复核原有 81 个喊声键。

译文保存在 `localization/zh_CN/textdb.po`，由 `textdb-phase3.json` 生成 `dat/database/zh/colourname.txt` 和 `shout.txt`。严格配对显示所需的完整正文另进入 UI 审核目录。集齐宝石的日志仍从原始颜色库只抽取一次英文规范颜色，再通过 `i.colour` 的 370 个颜色标签显示中文。

术语按语境使用：goblin 使用“地精”，hunter 使用“猎手”，silver 使用“白银”；forest green 的 forest 为普通森林，非“魔法森林”分支，rust 为颜色“铁锈色”，非云类别“锈尘”，fire orange 为“火橙色”，非装备属性“火焰强化”。斯芬克斯、玩家幽灵和背景名仅用于显示，数据库中的英文键不变。

## 显示接入与英文回退

颜色库继续使用已有的严格配对机制。正文、引用子项或源代码依赖发生未审核变化时，整个句子回退英文。上批施法失误中依赖随机颜色、发光颜色或花纹的候选现在也能取得中文，不再因缺少颜色库而回退。无躯体怪物等尚未审核的特殊语法仍保留原有回退边界。

普通喊声在原有的一次 `do_mon_str_replacements` 调用中填入中文代词与身体部位；先分别剥离中英文频道前缀并核对频道，声音、视觉消息与沉默判断继续使用英文逻辑。`getPairedShoutString` 使用当前已审核正文，拒绝恢复陈旧中文覆盖文件中的文本。

斯芬克斯谜语成功和失败分支均使用同一次加权选择产生的双语消息，不重复查询、不重抽形容词，也不改变谜语触发、目标选择、迷惑／混乱和噪音逻辑。怪物另行作出的专属谜语回应仍属于 `monspeak.txt`，不在本批覆盖范围。

谜语失败模板是两个直接相邻的引用，如 `@_riddle_prefix_@@_riddle_fail_general_@`。这类模板没有自然语言，原文与译文相同，不能依靠译文目录判定是否可显示。配对查询现在允许这种纯引用组合直接沿用模板，但每个被引用子项仍必须完整可译；含任何普通文字或空引用的组合不能使用该通道。缺少任一子项、组件译名或已审核正文时，整句回退英文。

随机物品命名库没有新增颜色引用；其数据库文件和生成逻辑不变。集齐宝石日志保留 `getSpeakString(..., true)` 的规范英文颜色查询。没有为了翻译重新生成名称或修改存档标识。

## 验证与剩余范围

新增原生检查覆盖：

- 全部 9 个颜色命名空间，每项使用 128 个种子，比较原始英文、中文递归结果与随机状态。
- 全部 370 个宝石颜色标签及切回英文的原文。
- `shout.txt` 的全部 92 个非空条目，使用杰西卡、塔兰泰拉和混沌孳生体，每项 12 个种子，检查频道、代词、怪物名称、原始英文与随机状态。
- 谜语成功／失败／有回应的失败三类分支，及鸦鸣／狂笑的可见和不可见消息。
- 纯引用组合中的缺译子项、含普通英文的引用模板，以及旧中文不可复活的负例。

验证结果和各文件导出清单见 [检查记录](database-02-checks.json)。未进行实际 Tiles 窗口视觉验收。
