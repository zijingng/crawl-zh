# WebTiles 宗教、技能列宽及鉴定反馈

1. 宗教窗口的称号、神宠、赐予的力量、消耗、概览、神力、神罚、补充和信仰提示原先写死在 HTML 中。现在通过现有 `language` / `ui_text` 配置读取已审目录，保留快捷键和高亮结构。神名标题按本地界面显示中文和原名。英文配置与缺失译文仍显示英文。
2. 技能菜单源码已经按显示列宽补齐名称，真正的问题是 WebTiles 文本缓冲每写一个汉字只前进一列。现在与终端一致按 `wcwidth` 前进，为双宽字符记录续列；导出 HTML 时不重复输出续列，并把字形宽度固定为 `2ch`。擦除或覆盖任意半列时清除旧字形，宽字符在行尾整体换行。顺便修复此写入循环遇到回车不推进指针的问题。此修复适用于共用文本缓冲，不仅针对技能名。
3. 神祇消息原先拿首字母大写后的说话者查规范神名，导致 `the Shining One` 对不上。现在只在查译文时使用规范神名；英文原消息、说话者、消息通道、神祇状态不变。武剑会的特殊说话者继续查既有条目。
4. 当前 `ui.po`、`textdb.po` 的“持握”统一为“持用”，术语表补充 `wield`，同步相关译文清单快照。历史 legacy 资料和已生成的旧 morgue 不追写。
5. 上次修复的是自动重排提示；鉴定卷轴的 `_identify` 使用独立的静默重排加手动输出路径。现在这条路径也优先使用完整物品显示名，覆盖重排、未重排和地面物品；查不到完整译名时整条物品名称回退原英文。数量、字母和鉴定操作不变。“这是一张鉴定卷轴。”本身已有译文。
6. F 键物品菜单的动态拼接标题改为两个完整、已审的显示模板，分别处理可以投掷和不能投掷的情况。英文文案保持不变。

验证：Windows Tiles 与原生测试程序编译成功；新增两项原生测试共 28 条断言通过；47 项 Python 检查通过。实际 WebTiles 写入和序列化函数经独立 C++ 编译测试，覆盖不同长度中文、英文、固定数字列、行尾换行、覆盖双宽续列、回车及增量刷新。真实浏览器读取序列化结果及现有 CSS，在 Consolas、Courier New 下数字列偏差小于 0.04 像素；宗教模板 40 个标签的中英文切换通过。原有宗教窗口、HUD、帮助窗口 JavaScript 测试继续通过。已审 UI / TextDB 来源依赖失配为零。

尚未执行线上 Linux WebTiles 整局验收。部署需要重新编译 WebTiles 游戏，并同步 `game.html`、`style.css` 等网页资源后刷新浏览器；仅替换游戏二进制不能更新 HTML 和 CSS。
