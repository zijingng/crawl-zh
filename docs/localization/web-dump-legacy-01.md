# 用原有 WebTiles 协议提供中文 morgue 链接

中文配置下按 # 生成角色文件时，先按原逻辑生成英文 `.txt`，再生成中文 `.zh.txt`。本轮让 `dump_char` 通过可选输出参数报告中文文件是否已成功写入并关闭；其原有返回值仍只表示英文导出是否成功。

命令处理器始终保留原英文 `dump` 通知，仅在中文导出成功后额外发送一条同样类型、同样字段结构的 `dump` 消息。第二条 `filename` 为经过过滤的原始文件名加固定 `.zh` 后缀。后缀必须在过滤后追加，因为原有过滤函数会删除文件名中的点号。原服务器按 `morgue_url` 拼接路径，原网页追加 `.txt`，于是两条消息分别链接到英文与中文文件。

未修改服务器 Python、网页 JS 或消息字段。聊天栏显示两条原有样式的 URL，以 `.zh.txt` 区分中文版。不改变聊天正文、milestone、保存退出及死亡 morgue 的原有通知。英文配置、显式禁用中文、中文文件打开／写入／关闭失败时不发送中文链接；即使旧中文文件仍在，也不会凭文件存在推断本次成功。

服务器只需重新编译游戏程序，保留原有公共 morgue 路径配置，并确保该路径允许访问 `.zh.txt` 文件；无需因本功能升级 WebTiles Python 服务或网页资源。

验证：原生文件导出测试覆盖中英文、禁用中文及将中文路径设为目录造成的打开失败，22 条断言通过；43 项 Python 测试通过，其中直接执行未修改服务端的消息处理函数，并隔离编译实际 C++ 消息发送函数及文件名过滤函数，验证生成两个原协议消息及 `.zh` 后缀。Node 测试执行未修改网页的 dump 处理函数，确认两种 URL 都追加正确的 `.txt`。详细结果见 [检查记录](web-dump-legacy-01-checks.json)。本地验证不包含完整 Linux WebTiles 编译及线上部署验收。
