# 英文回退方针审查

审查基线：工作区根 README.md 的“汉化方针”，官方 0.34.1 与当前工作区累积补丁。检查范围包括前几轮的 UI 接入、显示名称、TextDB 导出、语言配置及字体排版改动。没有将上游已有的全部中文数据视为已经审定。

## 结论

审查前存在不完全符合方针的改动，本次已修复下列问题。当前已管理的 UI 和 TextDB 路径通过了回归检查；不能据此声称所有上游旧译文都具有来源变更自动失效机制。

## 发现与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 模板与文字参数分别翻译 | 某个模板或参数缺译后，可能得到英文句子加中文参数，或反之 | 新增集中式 `ui_translation_group`；先检查所需译文是否全部存在，再决定是否使用中文。创建角色、法术列表/法术库和背包快捷键说明已接入 |
| 直接复用英文语法碎片 | 恐惧消息把带冠词的 `DESC_THE` 怪物名放入中文；技能增强说明可能混入英文所有格及英文连词 | 恐惧样例暂缓，中文模式也回退原英文整句；技能原因列表保留原英文对象与拼接分支，原因全部可译时才生成中文及中文连词。未接入的神力所有格使该句整体回退英文 |
| 显示宽度改造替代了英文格式路径 | 技能名由最小宽度格式改为截断，未来较长英文名可能被截断；施法菜单标题不再明确沿用原字节格式 | 中文译文存在时使用显示宽度处理，英文或缺译时恢复原 `%-15s`、`%-25.25s` 表达；法术容量提示也保留上游单复数及尾随空格表达作为回退 |
| TextDB 选用英文正文后仍查询中文子条目 | 缺译主条目展开 `[[引用]]` 或别名时可能夹入中文，不等同于原英文展开结果 | 英文回退状态沿整个引用和别名链传播；用独立临时数据库测试实际解析器，而不只检查导出文件 |
| “翻滚”说明的外部引用指纹只用于报告 | 引用的变异说明变化后，父条目仍可能继续导出 | 将已审引用的英文及中文指纹作为导出依赖；任何一侧变化或消失，父条目停止导出。结合运行时递归回退，父条目及引用一起使用原英文 |

## 已确认的边界

- `spell_title()`、`god_name()`、`skill_name()`、物品命名和英文 TextDB 原文件未被中文名称覆盖。名称显示层不改变脚本名称、查询键或存档数据。
- `ui_translate` 仅在中文模式匹配上下文和完整英文；缺译、来源变化或未审目录项返回调用处原文。英文模式下逐项核对当前编译目录的全部英文原文。
- TextDB 导出排除缺译、fuzzy、未审、来源指纹变化及依赖指纹变化的条目。`language = en` 的语言目录指针为空，不加载中文 TextDB 覆盖层；切换配置后需重启。
- 字体回退仅在主字体缺字时选择补充字体，五个区域仍独立配置。CJK 换行和双列处理是渲染能力改动，不替换英文文案；用户选择不同字体后不承诺像素布局与上游默认字体完全相同。
- 简单数值格式化、固定标签及合理段落/列表拼接不要求统一重写。复杂英文所有格未通过中文专用对象表达接入前，保留英文整句。

## 尚未完成的全局保证

第五批后仍有 14 个上游旧中文文件未纳入 PO 来源校验，详见 [覆盖报告](phase3-coverage.md) 的“未纳入本批 PO 管理的旧中文文件”。这些文件在中文模式仍可能被上游语言目录机制加载，不能保证英文更新后旧译自动失效；英文模式不会加载它们。本次没有为满足审查而批量删除现有旧译。后续新增范围与检查见 [第五批记录](phase3-static-05.md)，以下验证数字保留为本次审查当时的快照。

TextDB 的指纹失效在正常构建/导出时执行；直接修改数据后绕过构建运行旧产物，不具有运行时重新计算来源指纹的保证。本轮没有执行 GUI 排版验收，也没有把函数/目录测试等同于全游戏界面逐屏对比。
