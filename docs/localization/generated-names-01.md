# 程序生成名称的机器音译

中文界面只显示中文音译，不附英文原名。英文界面保持原文；存档、数据库键、配置、Lua 返回的规范名称和英文 morgue 不改写。

本次接入能从对象类型确认来源的三类名称：

- 未鉴定卷轴标签：只音译原来可见的随机标签，不查询卷轴真实类型。已鉴定卷轴继续使用术语表中的功能名称。
- 随机魔窟领主：怪物显示名、遭遇／击杀／相关状态的中文记录共用同一规则。固定独特魔窟领主继续使用已有正式译名。
- 自动生成的商店主人名：商店中文显示使用音译；地图写定的主人名和特殊商店名称仍走原有显示路径。

`ui_generated_name_arg` 只接受有明确生成来源的规范专名，不能用于整个英文句子、一般词汇或玩家输入。规则优先匹配字母组合，再将辅音、元音组合转为中文音节；双写辅音合并，词间分隔转为间隔号。固定表不读取网络、不调用模型、不消耗随机数。字母大小写不改变音译。例：`Fubb` → 富布，`Deeh` → 迪赫，`Ylod Wia` → 伊洛德·维阿。

英文模式、空名、非支持字符、过长名称和异常分隔会拒绝音译，交由现有完整英文回退路径处理。未知词汇不会因此被加入已审 TextDB，术语表里的固定译名不被机器替换。玩家名、玩家幽灵名以及来源不明确的神器标题、书名作者没有套用这条规则。

这是虚构拼写的近似音译，不是真实语言的读音推断；不同英文名可能产生相同中文音译。按用户选择不附原名，内部身份判断仍使用原英文及原有标识，因此不会合并实体或修改物品类型。

回归验证覆盖 1024 个种子生成的普通名称和卷轴标签、256 种卷轴标签在实际物品显示中的接入，以及魔窟领主、商店、中文记录与玩家幽灵边界；检查确定性、英文切换、原名不变、未鉴定信息不泄露和随机状态不变。既有相关遭遇、商店和双语 morgue 测试同步更新音译预期。

验证结果：相关 15 项原生用例、21,750 条断言通过；47 项 Python 检查通过。Windows Tiles 游戏及测试程序编译成功。全量 `[localization]` 串行回归在旧用例 `Monster speech deity and alternative target markers preserve English and fallback` 崩溃；该用例单独运行正常，存在用例间状态干扰，尚未修复，不能宣称全量通过。此前 161 个用例已完成逐项执行，相关音译／遭遇／商店／双语 morgue 另行独立运行通过。

后续补漏：魔窟领主描述页的正文原先在 `_describe_demon` 中直接插入英文名，现接入同一音译；外貌生成的哈希仍使用英文原名。新增描述用例覆盖三个名字及飞行／非飞行分支，检查标题、正文、原名和随机状态；与音译用例合计 15,948 条断言通过，Windows Tiles 已重新编译。进入魔窟的实际地图 Lua 也已复查：四位固定领主使用既有正式译名和符文译名，随机领主的入口提示不包含专名，遭遇列表中的专名走音译；神圣区域及付费符文提示保持中英文配对。地图／遭遇／地形与描述检查共 129 条断言，固定领主 Lua 检查另有 5 条断言，均通过。原英文 notes 和 milestones 保持不变。
