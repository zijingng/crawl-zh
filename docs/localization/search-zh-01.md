# Ctrl+F 中文搜索与双语前缀

仅在 `language = zh` 配置下，Ctrl+F 的匹配内容增加中文显示名和已审中文前缀。英文配置继续使用原来的英文匹配内容，英文查询也保留原始匹配内容，避免改变正则锚点含义。

## 使用

- `治疗药水`：按物品中文显示名搜索。
- `防具 && !!躯干防具`：查找防具，排除躯干防具。
- `神器 && 火抗`：按类别与抗性别名组合搜索。
- `魔法飞弹`：搜索已知包含该法术的法术书。
- `地下城:3`：按分支中文名与层数搜索，也支持全角冒号。
- `@长剑`：保留原有当前楼层限定。
- `=治疗药水`：保留原有字面匹配；`/` 开头或 `regex_search` 配置启用正则。

中文查询可以混用英文名称、原有英文前缀及 `&&`、`||`、`!!`、`<<`、`>>` 等既有布尔语法。一个对象的双语内容合并后只求值一次，避免英文匹配与中文匹配分别求值导致排除条件失效。

## 物品描述

原来的英文前缀整段保留，随后追加中文别名，例如：

```
{weapon} {Long Blades} {rF++} {武器} {长刃} {火抗++}
```

菜单／着色前缀同样在原有英文词之后追加中文别名。未知自定义标签只保留原文，不猜译。别名复用既有技能名称、装备紧凑词条翻译，并新增 `search.tag` 及地点冒号格式的已审条目；翻译前查阅术语表和现行译文，具体语境选择单一译法。

## 实现与英文回退

- 在 `stash.cc` 的地面物品、背包、商店及地形匹配入口增加中文别名；搜索结果身份、排序、去重、旅行目标仍使用原有英文数据。
- 中文名称复用物品、法术、商店、地形及分支的显示接口；未鉴定物品只按可见名称匹配，不读取隐藏的真实名称或神器属性。法术书本身没有未鉴定外观。
- `describe.cc` 只在显示路径追加中文前缀；规范英文描述、Lua 返回值和英文 morgue 路径保持英文。缺少已审别名或显示名称时保留原英文。
- 不修改共享的 `dat/clua/stash.lua` 和 `item_prefix`；自动拾取配置不会因新增中文标签改变匹配对象。法术书搜索的原始注释在中文配置下以英文生成，再由 Ctrl+F 单独附加中文法术名称。
- PCRE 中文正则叶子显式启用 UTF-8，中文字符类及量词按字符处理。内置 PCRE 的父级构建规则增加 UTF 支持能力，不修改 PCRE 子模块；普通英文正则仍使用原有字节模式。POSIX 后端继续使用原有实现。
- 搜索帮助译文在 `textdb.po` 维护，构建导出已审中文 TextDB，没有新增第二份帮助正文译文。

## 验证

定向原生测试覆盖中英文切换、英文与中文前缀同时保留、未鉴定物品、书中法术名、地面／商店／地形及地点匹配、布尔排除、中文正则、Lua 调用次数和随机状态。Windows Tiles `crawl.exe` 已重新编译；8 项原生测试共 180 条断言、33 项 Python 本地化测试通过。结果见 [检查记录](search-zh-01-checks.json)。
