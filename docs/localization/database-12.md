# database 第十二批：喷泉装饰消息

本批转向 `database/decorlines.txt`，完成 **49 个键、64 个候选**的补译，范围是喷泉的静态描述、神祇相关感想及引用关系已闭合的别名。全文件共有 132 个唯一键，仍有 83 个键待处理，主要包括 Lua、涂鸦、手／武器占位符和食物装饰消息。

## 翻译与数据审核

翻译前按完整单词查询术语表，命中和术语表哈希见 [预查记录](database-12-preflight.json)。使用“兽人”“卢戈努”“佐姆”“海妖”“无形水母”“血喷泉”等既定译法。神名及形态仍使用英文规范查询键，不把中文写入标识。

原文有一个重复键 `Jiyva peaceful fountain_blue`。TextDB 与审核解析器均采用后者覆盖前者的行为；因此本批按实际生效的“闪着微光的黏液”翻译。没有修改或擅自合并上游重复定义。

逐条核对普通叙述、随机候选、权重与别名引用。`sparkling_message` 中的轻盈、勇气、恶心及情绪变化仅描述原文中的短暂感受，不添加实际属性效果。没有把神祇名称、普通感想和法术／装备属性作机械替换。

译文同步进入 PO 与正式 TextDB 生成清单，条目范围登记为 `reviewed_subset`，只导出这 49 个已审键。其余条目不标为已审，缺项由规范英文处理。每个引用依赖保存源文及译文哈希。

## 显示适配与英文回退

`_walk_on_decor` 现在使用严格配对的 MiscDB 查询。神祇／默认／形态／种族的查找顺序、空结果判断、概率分支与频率保持原有逻辑。方括号仍在原位置选择一次，随后才计算原来的武器与手部字符串。

新的渲染函数保留英文手／武器替换及 `do_mon_name_replacements` 的一次调用。尚未适配的手／武器组件和随机名字会让整句回退英文，不生成中英混合句，也不为翻译重新生成随机姓名。未知引用及缺少已审正文同样整句使用英文。

本批不翻译 Lua 程序；原有配对接口只执行规范英文一次，未知程序／结果保留英文。`__NONE` 和空结果仍作为不显示消息的标记。源码和译文依赖哈希保护一并登记，仅刷新与本批代码基线完全匹配的已有依赖。

## 验证

新增原生测试实际加载 TextDB，对 49 个已审键各使用 128 个种子，比较规范英文、中文及后续随机状态。另覆盖未知引用、缺译、手／武器完整英文回退、`__NONE`，以及随机名称只生成一次。

数据检查逐条核对权重、引用、方括号组顺序与数量、PO 一致性、原始英文文件按字节不变。隔离数据测试修改哥萨戈子条目，确认该条目与引用它的别名旧译一并拒绝导出。

Windows Tiles 编译、工具测试及原生回归结果见 [检查记录](database-12-checks.json)。未进行实际游戏窗口视觉验收。整个 `dat/database` 仍未全覆盖。
