# database 第十六批：完成涂鸦词库与动态引用

本批补译并逐项校对 `database/graffiti.txt` 剩余 **45 个键、317 个候选**。包括作者署名、称号、课程广告、聚会、信仰评论、种族传闻、独特怪物评论、短句及复仇等。连同上一批的 13 个键，涂鸦文件 **58／58 个键**完成数据审核；生成清单改为 `whole_file`。

同时复核现有 13 个键的旧译：颜色、书写类型、爱憎动词、生死评价、大师课和入口句式继续沿用；补齐其对本批新增子条目的依赖。校对复仇原因时避免将英文宾格 `them` 误作“自己”，保留原文的对象关系。

翻译前已查询术语表的直接命中和复合词对应规范名，见 [预查记录](database-16-preflight.json)。神名、独特怪物名、种族、技能、物品名依照现行术语，例如“机甲哥布林”“猩红怨体”“阴影怨魂”“蜂巢护符”“武剑会”“唤发”“祈祷”。普通作者的个人姓名保留原拼写，种族、称号和括号说明译成中文；没有改写名字生成池或规范英文键。

## 显示与英文回退

增加装饰消息专用的随机神名、技能名配对适配器，复用已有 `display.god` 和 `display.skill` 目录。仍由英文路径选择一次，将同一个值用于中文显示。保留原先替换顺序，以及原函数在判断块内对未出现类别也会执行的随机抽取，避免改变后续游戏随机状态。原有 `do_mon_name_replacements` 保持不变，作为回归对照。

作者引用的 `ancestor name`、`bland name`、`any orc name` 明确按个人姓名处理；周围的“兽人”“另一个”等描述仍受译文审核约束。原始 `@RANDGEN@` 未接入姓名显示适配，选到它时仍整句回退英文，不重复生成姓名。

原文复仇候选有一个不存在的 `@graffiti_author_any@` 引用，正确的其他引用通常带两端下划线。本批保留这一上游问题，遇到它会整句回退英文。58 个键全部审核不代表所有随机分支均能显示中文。

所有涂鸦与颜色子条目建立精确正文及译文哈希依赖。运行时完整正文另绑定英文涂鸦、颜色、姓名池和相关 C++ 文件哈希；只刷新与本批修改前快照精确匹配的旧依赖。英文原始数据保持不变。

## 验证

对全部 58 个键逐项检查权重、引用、方括号选项个数、PO 正文及导出内容。原生测试每键使用 128 个种子，对照原始英文路径与后续随机状态，并验证中文结果没有遗留占位符；允许姓名保留拉丁字母。三类喷泉入口各用 256 个种子验证最终显示。另单独测试随机神名、技能名、重复标记、混合引用及原始随机姓名回退。

编译与测试结果见 [检查记录](database-16-checks.json)。未进行实际游戏窗口视觉验收。整个 `dat/database` 的其他文件仍需继续审核。
