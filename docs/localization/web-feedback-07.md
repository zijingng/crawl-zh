# 徒手菜单、楼梯操作和怪物提示

- `w` / `e` 共用装备菜单的徒手项原先只查 `i.ui`，导致利爪、尖牙与利爪、触手及形态攻击名回退。改为复用现有 `Form::uc_attack_display_arg`，并补齐普通“徒手”。未知攻击名仍整体保留原英文。
- 地形右键操作已经通过整条操作列表的翻译入口，但楼梯、目的地和门的六个完整标签缺译。补齐 `(<)上楼`、`(>)下楼`、查看目的地、开门、关门，保留命令字符及既有整句回退。
- WebTiles 怪物描述的 Description / Status / Quote 在 JavaScript 中写死。现在从现有 `ui_text` 目录读取“说明／状态／引文”，保留活动页高亮、页面组合和 `!` 快捷键。
- 怪物数值条的零值 `none` 改为显示目录中的“无”，覆盖意志、护甲、闪避；英文模式仍输出 `none`。
- WebTiles 怪物协议新增 `name_display`，使用 `monster_info::try_display_name`，原 `name`、类型、复数和标识不变。鼠标提示仅在中文配置下选择显示名，缺项／旧服务端回退英文；提示操作复用既有“右键：查看说明”，补齐“左键：选择目标”。怪物名通过文本节点转义，避免自定义名字被当作 HTML。

修改前核对了现有术语：利爪、尖牙与利爪、触手、徒手、意志、说明、状态、引文。没有新增一套怪物名译文。

验证：Windows Tiles 和原生测试程序编译成功；新增原生用例通过 20 条断言，实际生成老鼠说明以检查零意志和英文回退。新增 JavaScript 测试执行真实鼠标提示和怪物窗口模块，覆盖中文／英文／旧服务端、所有说明页组合、缺失显示名和特殊字符转义。既有神祇窗口、HUD 测试通过；47 项 Python 检查通过；已审 UI 来源依赖失配为零。

WebTiles 部署需重新编译游戏，并同步 `mouse_control.js`、`ui-layouts.js` 后刷新浏览器。本地没有执行完整 Linux WebTiles 构建或线上整局验收。
